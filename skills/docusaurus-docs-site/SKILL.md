# Docusaurus 文档站（从仓库产出直接生成）

把一个项目已有的 README / 实测日志 / 断言列表，变成**能发链接的静态站**。
典型场景：面试或答辩要"一个可以打开的链接"，而手里只有散落的 markdown。

## When to Use（何时用）

- 已有可验证的工程产出（README、verify 脚本、实测数字），缺门面
- 需要纯静态、零后端、零跟踪的站
- 不想碰 React 细节，只想写 markdown

## 先选型：文档站 还是 作品集页

**Docusaurus 是文档优先的**——侧栏、目录、多页导航都围着“读文档”设计。把它拿来当个人主页
会很别扭（首页永远是文档目录气质）。两种形态分开选：

| 要什么 | 用什么 | 实测代价 |
|---|---|---|
| 多页文档、侧栏、需要逐项自证 | Docusaurus | 13 页共 999 KB、JS 638 KB、761 个包、构建 ~40 s |
| 一屏讲完“我是谁 + 几个项目”的作品集 / 宣传页 | **Astro** | 单页 **8 KB、0 JS**、157 个包、构建 **6 s** |

```bash
npm create astro@latest <dir> -- --template minimal --no-git --yes
npm install && npx astro build     # 产物 dist/，首次装依赖 ~75 s
```

**不要为了动效给 Astro 加 React**——一引框架，“0 JS” 就没了，它唯一优于 Docusaurus 的点也随之消失。

作品集页的两条内容规则（用户已确认）：

1. **电话不放公开页**（会被爬虫抓），邮箱若要放就写变形（`name [at] domain`）；
   最稳是两个都不放，联系方式留在简历里，页面只负责证明真做过。
2. **数字只写能追溯到实测日志的**（verify 脚本输出、基准测值）；没核实过的先标占位，
   宁可留空也不要把估算写上去——公开页上的数字别人会当事实引用。

作品集原型与可复用的改造清单在 `%LOCALAPPDATA%\hermes\workspace\astro-作品集原型\README.md`。

## 最小可用骨架（4 个文件 + docs/）

```
package.json          @docusaurus/core + preset-classic ^3.6.0, react ^18.3.1
sidebars.js           { main: [{ type: 'autogenerated', dirName: '.' }] }
docusaurus.config.js  见下方关键字段
.gitignore            node_modules/ .docusaurus/ build/
docs/*.md             frontmatter: title + sidebar_position
```

`docusaurus.config.js` 必须写对的五个字段：

```js
url: 'https://example.com',      // 发 Pages 时改成 https://<user>.github.io
baseUrl: '/',                     // 发到 project pages 改成 '/<repo>/'
i18n: { defaultLocale: 'zh-Hans', locales: ['zh-Hans'] },
presets: [['classic', { docs: { routeBasePath: '/', sidebarPath: require.resolve('./sidebars.js') },
                         blog: false }]],   // 纯文档站：根路径就是文档，关掉 blog
```

- `routeBasePath: '/'` 让站点根 = 第一篇文档，不用另写落地页；
- `blog: false` 省掉一整套时间戳/作者字段的报错；
- 不 reference `src/css/custom.css`（没建就别写 `customCss`，否则构建直接失败）。

## 安装与构建（中国网络）

```bash
npm install --registry=https://registry.npmmirror.com --no-audit --no-fund
npm run build      # 产物在 build/，成功标志：[SUCCESS] Generated static files in "build"
npm run serve      # 预览 build/ 成品（默认 3000，可 --port 3100）
```

Docusaurus 依赖 ~1274 个包、约 3 分钟；`node_modules` 数百 MB，**别放进仓库**。
Node 需 ≥18（本机 v24 实测通过）。

## 验证"真的成了"（不看构建日志就下结论是错的）

```bash
find build -name '*.html' | wc -l        # 页数
find build -maxdepth 2 -name index.html  # 路由列表
grep -o '<title>[^<]*' build/index.html  # 标题与预期一致
```

再起 `npx docusaurus serve --port 3100 --no-open`，用浏览器打开并**断言 DOM**：

```js
document.title
document.querySelectorAll('nav.menu a').length     // 侧栏项数 == docs 页数
document.querySelectorAll('article table').length  // 表格是否渲染
document.querySelector('article p').innerText.slice(0,80)
```

截图只能证明"没白屏"，DOM 断言才能证明"内容进去了"。

## 坑（都踩过）

1. **H1 里别放行内代码。** `# 验证：`/root/x/verify.sh`` 会把标题挤成两行（代码块宽度撑开），
   改成 `# 验证` + 正文一行写路径。
2. **`onBrokenMarkdownLinks` 已废弃**（v4 会移除），警告可忽略；要消掉就挪到
   `markdown.hooks.onBrokenMarkdownLinks`。
3. **别用 `create-docusaurus` 脚手架**去生成一个全新站——它带一堆 demo 页（恐龙、博客、
   `custom.css`），删起来比手写四个文件慢。直接写最小骨架。
4. **文档里的数字必须来自实测日志。** 从 README 抄数字等于把旧数据固化；站点一旦发布，
   别人会当事实引用。改数字前先重跑验证脚本。
5. **写完立刻加一页的节奏**：每完成一项技术增量就补一页，不要攒到最后（攒完就没人写了）。

## 发 GitHub Pages

1. 改 `url` / `baseUrl` 两行；
2. `npm run build`；
3. 推 `build/` 到 `gh-pages` 分支，或仓库 Settings → Pages → Source 选 GitHub Actions（`.github/workflows/deploy.yml` 用 `actions/deploy-pages@v4`，需 `permissions: pages: write, id-token: write`）。

### 第一跑最容易踩的：Pages 根本没开

即使四步都做了，首次推送后 `build` job 可能全绿而 `deploy` 被跳过，唯一失败的是
`actions/configure-pages` —— 因为仓库还没启用 Pages。启用路径：
**Settings → Pages → Build and deployment → Source: GitHub Actions**（不要选 Deploy from a branch），
然后推一个空提交重新触发：`git commit --allow-empty -m trigger && git push`。
验证要看 `actions/deploy-pages` 这一步 success，不是只看 build。

### 推不上去时：先去 github-auth 查

git 调不靠（`CRYPT_E_NO_REVOCATION_CHECK`、“Credential Helper Selector”弹窗、
`ls-remote` 卡住、token 只能读不能推）全部归类为**认证/传输问题**，
已在 `github-auth` 技能的 Troubleshooting 表里逐条给出病因与修法，不要在本技能里重复实现。

## 清理

Windows 上 `npx docusaurus serve` 会留下 node 子进程：

```powershell
Get-CimInstance Win32_Process -Filter "Name='node.exe'" |
  Select-Object ProcessId,ParentProcessId,CommandLine   # 先确认哪一个是自己的
Stop-Process -Id <自己的 PID> -Force                    # 按精确 PID，绝不 taskkill /IM node.exe
```

`taskkill /FI "IMAGENAME eq node.exe"` 会连编辑器、Coze 运行时一起杀掉。
